# Step 1 — ingest from Confluence

Load `ba-rules` first. Read `ba-project.yaml`. MCP tools: `mcp__<atlassian.mcp_server>__…`, always with `cloudId: <atlassian.cloud_id>`. Read-only towards Confluence.

**Called from `/ba-sync` (skill `change-impact`):** phase A runs §1–§2 only (snapshot of the new versions — no working sources, no README, no `ba-project.yaml`); after the BA's OK on the CHG plan, phase B runs §3 for the changed pages. §5 is then done by `change-impact`, not here.

## 1. Fetch
| What | Call | Keep |
|---|---|---|
| Page body, exact | `getConfluencePage` · `pageId: source.page_id` · `contentFormat: html` | body → `page.html` |
| Page body, for reading | `getConfluencePage` · `contentFormat: markdown` | body → `page.md`; `version.number`, `version.createdAt`, `version.message`, `title`, `spaceId`, `parentId`, `authorId` |
| Children (if `source.include_children`) | `getConfluencePageDescendants` · `pageId` | id, title, version; then for each child the two calls above |
| Attachments | no MCP tool | list stays as in `source.attachments` (filled by the watch Action); files come via `inbox/` |

Each page (the main page and every child) is versioned on its own. A page whose fetched version already has a snapshot folder is "unchanged". If every page is unchanged and the set of children equals `source.children` → say "no new version", skip to §4 (inbox) and stop.

## 2. Snapshot (immutable, one folder per page)
For **each page separately** — the main page and every child — write `docs/00-source/confluence/<pageId>/v<N>/`, where `<N>` is that page's own version:
- `page.html`, `page.md` — exactly the `body` strings returned by MCP. Do not reformat, trim, fix or re-escape anything.
- `meta.json` — `{page_id, title, space_key, version, created_at, version_message, author_id, parent_id, fetched_at, sha256: {page_html, page_md}}`; the **main page's** `meta.json` also has `children: [{id, title, version}]` — the child ids and versions at fetch time. Compute the hashes after writing (`sha256sum` / `Get-FileHash`).

Child pages are never nested inside the parent's folder. Write a snapshot only for a page whose version has no folder yet: a new or changed child gets its own new `confluence/<childId>/v<M>/`, while the parent's existing `v<N>` stays as it is (its `children` list records what was there when it was taken; the current list lives in `source.children`).

Never edit or delete an existing `v<N>` folder. If it exists with different hashes, stop and report — something changed a snapshot.

## 3. Working sources (regenerated from the latest snapshot)
For the page and each child, write `docs/00-source/NN-<short-name>.md` (`NN` = next free number on first ingest; keep the same file name for the same page id later):

```
<!-- Source: Confluence <pageId> v<N> · "<title>" · <site> · fetched <date> · Generated by ingest-confluence -->
```
followed by the page content **verbatim** from `page.md`:
- Allowed: line breaks, heading levels, list and table formatting.
- Not allowed: summarising, rephrasing, correcting typos or numbers, reordering, dropping sections, **unescaping markdown artefacts** (keep `\~`, `\*`, `\_` exactly as MCP returned them, so quotes found in the working source are also found in `page.md`). Inconsistencies in the source are signal for later steps.

**Source keys.** Keys are short and stable; never use an ID prefix from `ba-rules` §2 (`DEC`, `REQ`, …) as a key; keys are unique across all sources; if a key from an earlier version still matches the same page or heading, reuse it.
- **Main page:** one key per top-level section (H2), e.g. `HO` (handoff), `CTX` (context), `W1`, `W2` (workshop / meeting minutes, numbered in source order). Reference: `[W2 · <H3 heading>]`.
- **Child page:** **one key for the whole child page**, derived from its title (e.g. `BR` for "Workshop brief", `W4` for "Workshop 4 minutes"). Its sections are its H2 headings. Reference: `[BR · <H2 heading>]`.

Update `docs/00-source/README.md`: table of files (file · what it is · `Confluence <id>` · `v<N>`), the "Source keys" table (key · meaning incl. meeting date if any · page id · exact heading — for a child page the page title), and "Known missing inputs" (anything the source references but does not contain — attached or linked files, spreadsheets — plus "attachments: check the page, put files into `inbox/`").

## 4. Manual files (`docs/00-source/inbox/`)
For each file other than `.gitkeep`: convert to markdown verbatim (same rules as §3), save as the next `NN-<short-name>.md` with header `<!-- Source: file <original name> · ingested <date> -->`, move the original to `docs/00-source/originals/`, add rows and source keys to the README. Unreadable file → leave it in `inbox/` and report.

## 5. Update ba-project.yaml
`source.version`, `source.snapshot_at` (= `version.createdAt`), `source.title`, `source.children`; `steps.ingest = {status: draft, source_version: N, updated: <today>}`. If later steps exist and were built on an older version, do **not** touch them — tell the BA to run `/ba-sync` instead.

## 6. Report (chat language)
Version and date, files written, source keys table, child pages, known missing inputs, inbox files processed. Remind: the snapshot is the baseline for `/ba-sync`. Append to `docs/run-log.md`. Propose commit `step 1: ingest Confluence <pageId> v<N>`.
