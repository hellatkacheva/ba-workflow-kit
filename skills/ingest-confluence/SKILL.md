# Step 1 — ingest from Confluence

Load `ba-rules` first. Read `ba-project.yaml`. MCP tools: `mcp__<atlassian.mcp_server>__…`, always with `cloudId: <atlassian.cloud_id>`. Read-only towards Confluence.

## 1. Fetch
| What | Call | Keep |
|---|---|---|
| Page body, exact | `getConfluencePage` · `pageId: source.page_id` · `contentFormat: html` | body → `page.html` |
| Page body, for reading | `getConfluencePage` · `contentFormat: markdown` | body → `page.md`; `version.number`, `version.createdAt`, `version.message`, `title`, `spaceId`, `parentId`, `authorId` |
| Children (if `source.include_children`) | `getConfluencePageDescendants` · `pageId` | id, title; then for each child the two calls above |
| Attachments | no MCP tool | list stays as in `source.attachments` (filled by the watch Action); files come via `inbox/` |

If the fetched version equals `source.version` and a snapshot folder for it exists → say "no new version", skip to §4 (inbox) and stop.

## 2. Snapshot (immutable)
Write to `docs/00-source/confluence/<pageId>/v<N>/`:
- `page.html`, `page.md` — exactly the `body` strings returned by MCP. Do not reformat, trim, fix or re-escape anything.
- `meta.json` — `{page_id, title, space_key, version, created_at, version_message, author_id, parent_id, fetched_at, children: [{id, title, version}], sha256: {page_html, page_md}}`. Compute the hashes after writing (`sha256sum` / `Get-FileHash`).
- `children/<childId>/page.html`, `page.md`, `meta.json` — the same for each child.

Never edit or delete an existing `v<N>` folder. If it exists with different hashes, stop and report — something changed a snapshot.

## 3. Working sources (regenerated from the latest snapshot)
For the page and each child, write `docs/00-source/NN-<short-name>.md` (`NN` = next free number on first ingest; keep the same file name for the same page id later):

```
<!-- Source: Confluence <pageId> v<N> · "<title>" · <site> · fetched <date> · Generated by ingest-confluence -->
```
followed by the page content **verbatim** from `page.md`:
- Allowed: line breaks, heading levels, list and table formatting, unescaping markdown artefacts (`\~` → `~`).
- Not allowed: summarising, rephrasing, correcting typos or numbers, reordering, dropping sections. Inconsistencies in the source are signal for later steps.

**Source keys.** Derive one key per top-level section (H2) of each working source, short and stable, e.g. `HO` (handoff), `CTX` (context), `W1`, `W2` (workshop / meeting minutes, numbered in source order), `DEC` is reserved — never use an ID prefix from `ba-rules` §2 as a key. Keys must be unique across all sources. If a key from an earlier version still matches the same heading, reuse it.

Update `docs/00-source/README.md`: table of files (file · what it is · `Confluence <id>` · `v<N>`), the "Source keys" table (key · meaning incl. meeting date if any · exact heading), and "Known missing inputs" (anything the source references but does not contain — attached or linked files, spreadsheets — plus "attachments: check the page, put files into `inbox/`").

## 4. Manual files (`docs/00-source/inbox/`)
For each file other than `.gitkeep`: convert to markdown verbatim (same rules as §3), save as the next `NN-<short-name>.md` with header `<!-- Source: file <original name> · ingested <date> -->`, move the original to `docs/00-source/originals/`, add rows and source keys to the README. Unreadable file → leave it in `inbox/` and report.

## 5. Update ba-project.yaml
`source.version`, `source.snapshot_at` (= `version.createdAt`), `source.title`, `source.children`; `steps.ingest = {status: draft, source_version: N, updated: <today>}`. If later steps exist and were built on an older version, do **not** touch them — tell the BA to run `/ba-sync` instead.

## 6. Report (chat language)
Version and date, files written, source keys table, child pages, known missing inputs, inbox files processed. Remind: the snapshot is the baseline for `/ba-sync`. Append to `docs/run-log.md`. Propose commit `step 1: ingest Confluence <pageId> v<N>`.
